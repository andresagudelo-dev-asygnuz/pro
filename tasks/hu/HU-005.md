# HU-005 - Inscripción de equipo / jugador a torneo

## Historia
Como jugador verificado o capitán de equipo
Quiero inscribirme (o inscribir a mi equipo) a un torneo abierto
Para participar y ser incluido en la tabla de posiciones y resultados.

## Criterios de aceptación (GIVEN/WHEN/THEN)
1. Inscripción exitosa de equipo a torneo con cupos
- GIVEN un torneo en estado `abierto a inscripciones` con cupos disponibles
  WHEN un capitán válido envía la inscripción de su equipo con la lista mínima de jugadores requerida
  THEN el sistema registra la inscripción en estado `confirmada`, descuenta un cupo y notifica al promotor.

2. Inscripción de jugador individual (si el formato lo permite)
- GIVEN un torneo cuyo formato admite inscripciones individuales
  WHEN un jugador verificado se inscribe
  THEN el sistema registra su inscripción y lo asigna a un equipo "libre" o lista de espera según reglas del torneo.

3. Validación de verificación de edad (RF-007)
- GIVEN un jugador sin verificación de edad `aprobada`
  WHEN intenta inscribirse (individual o como miembro de equipo)
  THEN el sistema bloquea la inscripción para ese jugador y muestra mensaje remitiendo a HU-002.

4. Cupos agotados
- GIVEN un torneo sin cupos disponibles
  WHEN un equipo intenta inscribirse
  THEN el sistema ofrece lista de espera o rechaza con mensaje explícito según la configuración del torneo.

5. Cancelación de inscripción
- GIVEN una inscripción `confirmada`
  WHEN el capitán la cancela antes del cierre de inscripciones
  THEN el sistema libera el cupo y notifica al promotor.

## Notas de alcance (Opción A Acotada)
- Para este sprint la cancelación la hace el propio capitán / jugador (`registered_by = auth.uid()`) o el promotor (`tournaments.owner_id = auth.uid()`). Notificar automáticamente al promotor al cancelar queda pendiente para Sprint 6.
- La "lista de espera" ya está modelada en DB (`registration_status`) y en la UI del promotor. El flujo de moverse automáticamente de `lista_espera` a `confirmada` cuando se libera un cupo lo dejamos out of scope — el promotor lo ejecuta manualmente con un `update` de status (el trigger `sync_tournament_slots_on_status_change` mantiene `slots_filled` coherente).
- Inscripción solo-player no valida el formato del torneo (MVP): cualquier torneo admite solo/equipo. La restricción por `tournament_format` queda como mejora cuando se añada el campo `allows_solo`.
