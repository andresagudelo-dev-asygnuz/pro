# Test plan · HU-003 Perfil 4 bloques + visibilidad (RF-002)

Historia: `tasks/hu/HU-003.md`.
Migración canónica: `apps/web/supabase/migrations/20260417140000_g4_sprint2_profiles.sql`.

## Scope

- `profiles_core` (1:1 con `auth.users`): identidad básica + slug único.
- `profile_field_visibility (user_id, field, visibility)` con visibility en
  `{publico, promotores, privado}`. Una fila por campo que el usuario quiere
  sobreescribir respecto del default del catálogo `visibility_fields`.
- Catálogo `visibility_fields(field, default_visibility)` seed con todos
  los campos editables del perfil.
- Gate a `/perfil`: si `age_verifications.status != 'aprobada'`, redirect a
  `/verificacion`.
- Vista pública `/u/[slug]` respeta visibility por campo y por viewer role
  (anónimo / jugador / promotor).

## UI smoke test

1. Con user ya verificado (HU-002), navegar a `/perfil`.
2. Completar Bloque 1 (nombre, DOB, ciudad…). Cambiar visibility de `phone`
   a "promotores" y `dob` a "privado". Guardar.
3. Abrir `/u/<slug>` en pestaña anónima → phone y dob ausentes.
4. Login como promotor → phone visible, dob ausente.
5. Login como mismo user → todos los campos editables visibles en `/perfil`.
