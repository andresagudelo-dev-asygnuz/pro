# HU-002 - Verificación de edad con documento de identidad

## Historia
Como jugador recién registrado
Quiero cargar mi documento de identidad para verificar que soy mayor de edad
Para desbloquear el perfil y poder inscribirme a torneos del MVP1.

## Criterios de aceptación (GIVEN/WHEN/THEN)
1. Carga de documento válido
- GIVEN un jugador recién registrado
  WHEN sube un documento de identidad con formato permitido (JPG/PNG/PDF, tamaño máximo definido)
  THEN el sistema registra la solicitud de verificación en estado `pendiente` y muestra mensaje claro de que el perfil queda bloqueado hasta aprobar.

2. Aprobación de verificación
- GIVEN una solicitud de verificación en estado `pendiente`
  WHEN el mecanismo de verificación (externo o admin manual, según ADR-003) aprueba la edad del jugador como +18
  THEN el sistema marca la solicitud como `aprobada`, desbloquea el perfil y permite la inscripción a torneos.

3. Rechazo o menor de edad
- GIVEN una solicitud en estado `pendiente`
  WHEN la verificación concluye que el jugador es menor de edad o el documento no es válido
  THEN el sistema marca la solicitud como `rechazada`, informa al jugador con motivo y mantiene el perfil bloqueado para funcionalidades del MVP1 (solo +18).

4. Bloqueo de inscripción sin verificación aprobada
- GIVEN un jugador con verificación `pendiente` o `rechazada`
  WHEN intenta inscribirse a un torneo (RF-004)
  THEN el sistema bloquea la acción y muestra mensaje remitiendo a completar la verificación.

5. Privacidad del documento
- GIVEN un jugador con documento cargado
  WHEN cualquier otro usuario (jugador, promotor o visitante) consulta su ficha
  THEN el documento de identidad nunca es visible: el valor por defecto del campo es `privado` y no puede ser elevado a `promotores` ni `público`.

## Dependencias
- RF-007 (`docs/01-requisitos-funcionales.md`).
- HU-001 (debe existir la cuenta).
- G3 ADR-003 (mecanismo concreto de verificación): resuelve si se integra servicio externo o si MVP arranca con verificación manual por admin.

- [ ] Backend: middleware que bloquea endpoints sensibles (inscripción a torneo, edición de campos de adulto) si la verificación no está `aprobada`.
- [ ] Frontend: pantalla de carga de documento con preview, validación de tipo/tamaño, feedback de estado.
- [ ] Frontend: banner persistente en el perfil mientras la verificación esté pendiente o rechazada.
- [ ] DB: storage seguro para el documento (Supabase Storage con bucket privado u equivalente), tabla `age_verifications` con RLS.
- [ ] QA: tests de flujo feliz + rechazo + bloqueo de inscripción sin verificar; prueba de que el documento nunca se expone en respuestas públicas.
