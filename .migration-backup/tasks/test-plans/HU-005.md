## Scope

- Tablas `teams`, `team_members`, `tournament_registrations`.
- CHECK `tr_team_xor_user`: exactamente uno de `team_id` | `user_id`.
- UNIQUE parciales: `tr_unique_active_team`, `tr_unique_active_user`
  (previenen doble inscripción donde `status <> 'cancelada'`).
- Trigger `enforce_tournament_capacity` (INSERT): valida torneo abierto +
  cupos antes de permitir inscripción confirmada; actualiza `slots_filled`
  atómicamente bajo `for update`.
- Trigger `sync_tournament_slots_on_status_change` (UPDATE, Sprint 6):
  - `confirmada → !confirmada` → libera cupo.
  - `cancelada|lista_espera → confirmada` → valida torneo abierto
    (`tournament_not_open`) + cupos (`tournament_full`).
- Función SECURITY DEFINER `find_unverified_users(uuid[])`: bypassa RLS de
  `age_verifications` para que el capitán pueda validar a sus miembros.
- RLS `tr_update_self_or_owner` (Sprint 6):
  - `USING`: `registered_by = auth.uid()` OR owner del torneo.
  - `WITH CHECK`:
    - owner del torneo → puede setear `confirmada|lista_espera|cancelada`.
    - `registered_by = auth.uid()` → solo puede setear `cancelada`.

## UI smoke test

1. Login como jugador verificado. Navegar a `/tournaments/[id]/register` de
   un torneo abierto.
2. Flujo equipo: crear team con 1 miembro extra que SÍ esté verificado →
   submit → "Inscripción confirmada". Ver en `/tournaments/[id]/registrations`
   (logueado como owner del torneo) que aparece la fila.
3. Flujo equipo: agregar miembro NO verificado → submit → error "Hay 1
   miembro(s) sin verificación" sin crear fila.
4. Cancelar inscripción desde `/tournaments/mine` (como jugador) → status
   `cancelada`, cupo liberado (chequear `slots_filled` en psql).
